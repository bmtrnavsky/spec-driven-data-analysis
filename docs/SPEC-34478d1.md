## Part 2: new findings

### NEW-1 (HIGH): M7 tail window; chain growth after the last dda commit is never pinned
**Repro (exact M7 threat model, no git trickery):** lock → packet → approve spec (dda commits,
trailers written) → snapshot `.analysis` + heads mirrors (T0) → two FAILED goldfish rounds → restore
the T0 prefix and the T0 mirrors → re-run with a pass stub.

```
[control] re-run rc: 1 :: round 1 already ran twice in this lineage ...   G3 pass: False
[attack]  re-run rc: 0 :: goldfish teardown: round 1: pass; round 3: pass  verify problems: 0 | G3 pass: True
```

**Root cause:** `Dda-Chain-Head` trailers ride only on dda-made commits (`lock`, `amend`, `approve`).
Review rounds, runs, profiles and runlog appends happen between commits and are pinned by nothing but
the agent-reachable heads mirror. The in-repo probe `n_prefix_mirror_rollback` passes only because
its fixture happens to end with `approve` commits after the exposure. Its premise ("only git
checkpoints can catch this") holds only for evidence older than the last commit.

**Invariant I15:** every append to a sticky-consequence chain (review calls, runs, lineage, runlog
exposure) must be pinned in a medium the agent cannot roll back *before the append's consequence is
observable*. Either pin at append time (out-of-workdir append-only log keyed by workdir id, held by a
process the hook guards), or make gates that read the chain require a checkpoint at least as new as
the chain head (G3, G7 and `review run` refuse while `live_seq > newest_checkpoint_seq` on a sticky
chain, and dda auto-commits a checkpoint after each sticky append).

**Classification:** DESIGN FLAW (the pin medium is coupled to an unrelated, infrequent event).

**Acceptance test:** new probe `n_prefix_m7_tail_g3.py`, expected `G3-STILL-FAILING`, vuln
`G3-LAUNDERED-VULNERABLE`. Control = no restore. Mutation class: **function revert** of the new
"checkpoint must cover head" guard. Register a new scenario `pre-I15 unpinned tail` and validate with
the full arm matrix plus a historic arm at `34478d1`, which must print the vuln token.

### NEW-2 (HIGH): the M7 floor is erasable through hook-allowed git ops
**Repro:** fixture as NEW-1, but the failures are checkpointed (approve after the 2 failed rounds),
then the T0 prefix and mirrors are restored.

```
[control] checkpoints seen: 2 -> re-run rc 1 "below committed checkpoint", G3 pass: False
[flood]   201 x `git commit --allow-empty` -> checkpoints seen: 0 -> re-run rc 0, verify problems 0, G3 pass: True
[reflog]  commit-tree + update-ref + `reflog expire --expire=now --all` + `gc --prune=now`
          -> checkpoints seen 0, sticky flag False, verify problems 0 (exposure fixture)
hook (bound session): ALLOW `for i in $(seq 250); do git commit -q --allow-empty -m f$i; done`,
  ALLOW `git reflog expire --expire=now --all`, ALLOW `git gc --prune=now`, ALLOW `git update-ref -d`,
  ALLOW `git branch -f/-D`, ALLOW `git checkout --orphan`, ALLOW `git replace`
```

**Root cause:** `_scan_chain_checkpoints` stops at the newest 200 shas across `--all` plus the
reflog, so the floor is a sliding window. The reflog, which the design names as the survivor of
rewrites, is deletable by an allowed command. There is also a benign trigger: a workdir inside a busy
repo loses its floor with no attacker, because unrelated commits fill the window. The ea94356 sticky
pin rides the same floor (flag returns False in every bypass), so "verified reads" fall with it.

**Invariant I7‴:** the checkpoint set is complete and monotone. No count cap. Scan trailer-bearing
commits only (`git log --all --reflog -z --format=%H%x00%B --grep='^Dda-Chain-Head:'`, one
subprocess). The newest checkpoint seq per chain is also recorded outside git (the pin store from
I15), so deleting history cannot lower the floor. Any shrink of the checkpoint set relative to that
record is itself a §3.2-case-8 failure.

**Classification:** DESIGN FLAW (git history is agent-mutable; treating it as the only floor is the
flaw). The cap alone is a local patch, and removing it still leaves the reflog-expire path open.

**Acceptance tests:**

- `n_prefix_m7_flood_g3.py`, expected `G3-STILL-FAILING`. Mutation class: **helper mutation**
  (re-introduce `len(shas) >= 200`). It must flip, which also exercises NEW-7.
- `n_prefix_m7_reflog.py`, expected `ROLLBACK-DETECTED`. Mutation class: **function revert** of the
  out-of-git floor comparison.
- Add `reflog expire`, `gc --prune`, `update-ref -d`, `branch -D/-f` to `n_hook_gitops` DESTRUCTIVE.
  Patch-kind mutation under the existing `pre-N10` scenario.

### NEW-4 (MED): git-op verdict is a porcelain blocklist; aliases, plumbing and escapes pass
**Repro (bound session, evidenceguard):** ALLOW for each of:

- `git -c alias.nuke='clean -fdx' nuke`
- `git config alias.sv 'stash -u' && git sv`
- `git checkout-index -f -a`
- `git read-tree -u --reset HEAD~1`

[BLOCK: `git stash -u`, `git clean -dxf`, `"git" stash`, `/usr/bin/env git clean -fdx`, python

**Root cause:** `_git_op_verdict` enumerates bad porcelain verbs after naive tokenization. Git's verb

**Acceptance test:** extend `n_hook_gitops.py` DESTRUCTIVE with the 9 forms above. Patch-kind
mutation (re-introduce the blocklist) under `pre-N10`. Re-validate the record.

### NEW-5 (MED, harness): the revert machinery rewrites live product code in place, with no lock and lossy restore
**Observed:** at review start the live checkout had `scripts/ddalib/chain.py` and `ledger.py`
modified: `_append_locked` minus both M7 raises plus `assert` in place of the CAS raises, and
`_checkpoint_problems` returning `[]`. That is a concurrent `unittest discover` (running since 10:51)
mid-revert. It cleared when the run ended.

**Deterministic repro of the permanent variant** (scratch worktree): `rA = apply_unit(... no_M7)`;
`rB = apply_unit(... historic)` (B snapshots A's mutated file); `rA(); rB()`. Result:
`left mutated: True | 'DERIVED no_M7' present: True`. This is byte-for-byte the diff seen live.

`restore()` uses `write_text`, which on Windows rewrites LF files as CRLF. The live checkout now
holds `w/crlf` for `chain.py`, `hooks.py` and `stage8.py` (index `i/lf`).

**Risks:**

- `git commit -a` during a run commits de-fixed security code;
- a kill/timeout (no `finally`) leaves it de-fixed;
- any dda CLI or hook process importing from the checkout mid-run executes the weakened guard;
- the line-ending churn caused NEW-6.

**Invariant I16:** reverts never touch the source checkout. Each arm runs against a private copy
(temp worktree or `PYTHONPATH`-shadowed copy of `scripts/`). If in-place mutation is kept, a
repo-level exclusive lock is required, plus `write_bytes` restore of the exact original bytes, plus a
startup check that refuses to run on a dirty `scripts/ddalib`.

**Classification:** DESIGN FLAW (shared mutable target).

**Acceptance test:** `tests/revert/test_isolation.py`: run two `apply_unit` arms interleaved as above
and assert the source file is byte-identical (sha256 of raw bytes) afterwards. Mutation class:
**harness mutation** (restore via `write_text`, no isolation) must fail it.

### NEW-6 (MED, harness): committed PREMISE.json fails on a clean checkout of its own commit
**Repro:** fresh `git worktree add --detach <tmp> 34478d1`, then `python -m unittest tests.test_premise`

creates the worktree) must pass. Mutation class: **harness mutation**: hashing raw bytes must fail

### NEW-7 (MED, harness): premise freshness covers the anchor function, not its dependency closure
**Repro (scratch worktree):** change `_scan_chain_checkpoints` cap `>= 200` → `>= 2`.
`check_pair` → both `pre-M7` records **FRESH**. `n_prefix_m7_chain` → `PREFIX-REFUSED-BY-CHECKPOINT`,

**Root cause:** `fixed_units` hashes only the AST of the anchored function (`chain._append_locked`,
`ledger._checkpoint_problems`). The guard's security depends on `chain_checkpoints`,

fixtures are too small (≤ 5 commits) to exercise them.

**Invariant I14′:** a premise record hashes the anchored function plus every `ddalib` function it
reaches through its static call graph (or simply the whole defining module(s), accepting more
re-validation churn). Every numeric bound inside that closure needs a probe that crosses it.

**Classification:** DESIGN FLAW in the validator (certification scope ≠ dependency scope).

**Acceptance test:** the helper mutation above must make `test_premise` report STALE, and the new
`n_prefix_m7_flood_g3` (NEW-2) must flip under it. Mutation class: **helper mutation**, new registry
kind `"helper"` alongside `"function"` / `"patch"`.

### NEW-8 (LOW, harness): oracle audit is syntactic; recorded verdicts are never re-checked
**Repro:** `audit_oracle` returns `[]` (accept) for:

- a bare `print("FINDING: <expected>")`;
- `from probelib import finding as emit`;
- conditions padded with `"" in "x"`, `x[0] == 0`, or any variable named `out`;
- a `except Exception as e: msg = str(e)` catch-all.

`check_pair` returns `None` (fresh) for a forged record with `reverted.token == fixed.token` (no
flip), `historic = {"commit":"deadbeef","token":"ANYTHING"}`, `cross_flips=["everything"]`.

**Root cause:** freshness is checked; semantics are not.

**Fix (cheap, do it):** `check_pair` asserts:

- `fixed.token == MANIFEST.expected`;
- `reverted.token == MANIFEST.vuln`;
- `historic.token == MANIFEST.vuln`, unless the scenario has `fix_commit: None`;
- `cross_flips ⊆ declared_cross`;
- `validated_at` is an ancestor of HEAD.

Acceptance: the forged record above → `BAD-RECORD`. Mutation class: **harness mutation**.

**Accepted risk:** a data-flow-sound oracle audit. Probes are authored by the same trusted party as
the fixes, and the audit exists to catch honest bare-exit-code mistakes, which it does (the
`bare_rc_control` case is rejected). Adding a lint rule forbidding direct `FINDING:` prints and
aliased `finding` imports is enough.

### NEW-9 (LOW, accepted risk): trailers are unauthenticated
Any commit message containing `Dda-Chain-Head: .analysis/runs.log 999999 x` is honoured by
`_scan_chain_checkpoints`. (This follows from the code and was not run end to end.) The effect is
fail-closed: every later append and G9 refuses forever, and because the reflog keeps it, it is hard
to clear. This is a wedge, not a laundering path, and an agent with shell already has cheaper ways
to break a workdir. **Accept**, but document a human recovery path (`dda checkpoint forget <sha>`,
human-only via `human_only_block`).
